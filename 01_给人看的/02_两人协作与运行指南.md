# 两人协作与运行指南

建议：代码和说明用GitHub私有仓库 + GitHub Desktop，行情和大体积结果用网盘按版本共享。首次发本压缩包，后续不反复互相覆盖整个文件夹。
Git用于保存每次修改及其原因；分支是独立修改副本；PR是合并前让另一人核对的修改单。

## 表弟第一次接收

1. 完整解压，进入 `02_机器运行项目`。先看报告，无需安装Python。
2. 需要运行时，打开该文件夹，在资源管理器地址栏输入 `powershell` 后回车。
3. 确认Python位置；以下用你的 `C:\ProgramData\miniforge3\python.exe` 举例，表弟应改成自己的路径。
4. 按顺序执行：

```powershell
& 'C:\ProgramData\miniforge3\python.exe' -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r outputs\strategy_universe\20260828_113225_t1expiry\requirements_reproduction.txt
& '.\.venv\Scripts\python.exe' -m unittest discover -s tests -v
& '.\.venv\Scripts\python.exe' -c "from covered_call.query import StrategyUniverse; u=StrategyUniverse(); print(len(u.registry))"
& '.\.venv\Scripts\python.exe' scripts\verify_strategy_universe.py --run outputs\strategy_universe\20260828_113225_t1expiry --skip-replay
```

成功标志：测试末尾OK；查询显示576；核验显示VALIDATION PASSED。`--skip-replay`只核验现有结构和账本，不重跑全部策略。去掉它可做完整独立复跑，耗时更长。原Python版本见同批次runtime_versions.json；若锁定依赖安装失败，先核对Python版本，不要随意升级后宣称完全复现。
默认查询已按项目位置寻找结果；直接运行其他旧入口时，请保持工作目录为机器项目根目录，并优先用 `--run` 显式指定批次。
备兑重新全量运行见README_Strategy_Universe.md。第一次接收不要先同步数据库，以免换掉冻结数据基线。
数据库同步需要自己的配置：复制工具包中的“数据库配置示例.json”为同目录“数据库本地配置.json”并填写；此文件不提交Git。

## 建立代码仓库（只需一次）

1. 安装并登录GitHub Desktop；选择 File → New repository，命名 options-research，选一个新的本地文件夹。
2. 将本共享包中的说明和机器项目复制进去，保留随包提供的 `.gitignore`。检查 Changes 列表没有行情、输出大表、压缩包、密码配置。
3. 填写 Summary（如“建立研究基线”），点 Commit to main，再点 Publish repository，勾选 Keep this code private。
4. 网页仓库 Settings → Collaborators → Add people，添加表弟账号；他接受后，在Desktop中 File → Clone repository，选择该仓库。
5. 数据及outputs单独从共享包复制到双方相同的相对目录。数据不会因为Pull自动更新。

## 每轮更新的固定流程

1. 开始前 Fetch origin / Pull origin，确认没有待同步修改。
2. Current branch → New branch，例如 research/margin-cap；一轮只改一个问题。
3. 你定义研究假设、成本和验收标准；表弟实现，或交换角色。改账本的人不独自完成最终审查。
4. 跑测试和固定样本复核。提交信息写清“改了什么、为什么、是否影响历史净值”。
5. Commit → Push origin → Create Pull Request；另一人看变更、结果和测试后合并。
6. 两边Pull后再开展下一轮。发生冲突时逐段核对，禁止直接用“我的覆盖你的”处理账本代码。

## 数据版本约定

每个批次保留 run_id、代码提交号、参数文件、依赖版本、data_mart manifest和SHA256、实际数据截止日、验证状态、结果链接。
新数据另存新版本；旧快照不可覆盖。对账先比数据哈希和参数，再比净值，最后讨论策略。
输出修复保留旧批次和修复说明；只有核验成功后更新latest_run指针。失败运行也保留原因。
若暂时不用Git：版本包命名“期权研究_日期_v序号”，一人维护主版本，另一人只提交修改文件及变更说明；每次合并前备份。

GitHub普通Git文件上限为100 MiB；大数据不随代码仓库提交，避免后续历史迅速膨胀。
官方操作依据：[Desktop入门](https://docs.github.com/en/desktop/overview/creating-your-first-repository-using-github-desktop)、[推送修改](https://docs.github.com/en/desktop/making-changes-in-a-branch/pushing-changes-to-github-from-github-desktop)、[大文件说明](https://docs.github.com/en/desktop/configuring-and-customizing-github-desktop/about-git-large-file-storage-and-github-desktop)。
